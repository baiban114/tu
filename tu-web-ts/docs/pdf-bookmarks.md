# PDF 文档书签

PDF 摘页与全文块的侧栏会展示 PDF 文件自带的 outline。PDF.js 不提供改写原始 PDF 的接口，因此用户添加的书签保存在当前文档中的 `pdfExcerptBlock` 节点属性里，并与 PDF 自带目录合并展示。

## 交互规约

- PDF NodeView 的标题栏后使用单一工具栏承载页码导航、缩放指示和 PDF 操作按钮，不覆盖页面内容。页码导航在块宽内居中，窄宽度时工具栏自动换行，缩放指示位于工具栏右侧。工具栏显示当前页与 PDF 总页数，并支持上一页、输入页码回车跳转、下一页。当前页按 PDF 可视区域中心所在页计算，滚动、缩放、侧栏宽度变化和书签跳转后会同步更新；当前页页面边框也会高亮。
- 文件名、摘页范围和裁剪比例等会动态变化的资源坐标信息作为标题输入框后的独立 `span` 展示，空间不足时省略；它不参与标题表单，也不占用下方唯一工具栏。
- 摘页模式只允许跳转到该摘页实际包含的页码范围。输入非整数或范围外页码时，导航条就地提示允许范围并保留当前阅读页，不静默忽略。
- 点击 PDF 块或书签栏的「添加书签」即创建书签，不打开填写表单。新书签名称固定为「未命名书签」，页码取点击时 PDF 可视区域中心所在页；没有可测量页面时才回退到摘页起始页。
- 新书签立即追加到书签栏末尾并被选中。用户需要可读名称时再通过右键菜单重命名。
- 自定义书签支持右键菜单「重命名」「删除」。重命名在树节点行内完成，Enter 或失焦保存，Escape 取消；空名称不保存。删除沿用确认框，避免误删。
- 自定义书签可通过鼠标拖动调整树形层级和同级顺序。拖动不得触发书签跳转；行上下边缘分别表示插入到目标书签之前/之后，行中部表示放入目标书签内部并追加为子项。
- PDF 自带 outline 与页面目录保持只读，不显示书签菜单，也不能拖动。自定义书签可成为父项，也可在展开的父项内部继续排序。
- 通用树负责行选择、展开、右键菜单生命周期、内联重命名与拖动排序。PDF 适配层负责 `PdfSidebarNode -> TreeNode` 转换、当前可见页判定、自定义书签权限及 `bookmarks` 持久化，不另写递归树交互。
- 右键菜单通过 `TreeListPanel` 的 `contextMenuItems` 提供项目，并在 `menuAction` 中处理业务动作。菜单挂到 `body`、使用 `useViewportClampedFixedPanel` 钳位，且须支持点击外部与 Escape 关闭。
- 点击书签仍会跳转到当前 PDF 块中的目标页。摘页模式下点击块范围外的既有自定义书签时，切换到该页作为单页摘页；新增书签只记录当前可见页。

### 复用边界

`TreeListPanel` 的通用契约包括受控/非受控展开、单/多选、可选同级与嵌套拖拽、右键菜单项和行内重命名。领域组件通过 `canDrag`、`canDrop`、`isRenamable` 与 `contextMenuItems` 声明权限，通过 `reorder`、`rename`、`menuAction` 接收结果并负责持久化；树组件不直接修改业务数据。嵌套拖放由 `allowDropInside` 显式开启，领域层仍需在 `reorder` 中拒绝将父项拖入自身后代；未提供上述可选属性时，既有资源选择树的行为保持不变。

## 持久化

- Tiptap 文档 JSON 中保存为节点属性 `bookmarks`：`{ id, title, pageNumber, parentId? }[]`。`parentId` 为空或省略表示根书签；数组顺序表示同父项下的显示顺序。
- Markdown 兼容序列化写入 `<!--tu:pdf-excerpt ... bookmarks="..."-->` 的 `bookmarks` 属性。
- 拖拽排序或调整层级后立即写回节点属性，刷新后保持。读取旧数据时兼容无 `parentId` 的平铺书签；悬空父项、自引用和循环父子引用会回退为根节点。重命名只修改 `title`，不改变 `pageNumber` 和树位置。
- 书签属于当前文档中的 PDF 块，不会修改上传的 PDF 正本。

## 局部渲染与滚动稳定性

- PDF 页面采用按视口懒渲染。进入渲染前，页面容器必须按 PDF 页面宽高比预置接近最终尺寸的占位高度；占位更新不得让整篇文档的总高度从固定 `120px` 逐页增长，否则拖动滚动条时可视锚点会被反复推向顶部。
- PDF 目录解析与首屏渲染并行启动。目录构建不得阻塞首屏页面容器、观察器和第一页渲染任务；目录返回后再更新侧栏，失败时仍允许正文阅读。
- 页面渲染调度必须始终以当前视口页为最高优先级，并预取相邻页面。快速滚动离开某页后，其排队任务应被清理，远距离在途任务应被取消；不得让旧页面继续占用渲染并发容量。
- 页面 host 暂时为零宽、尚未挂载或渲染后仍无有效 canvas 时，使用有上限的短延迟重试。只有当前页在重试耗尽后仍无法出图时展示错误；单个异常页不得中断其他页面。
- 页面首次渲染和重新栅格化期间保留原有几何占位与可见 canvas，UI 用轻量 loading 标记未出图状态。渲染成功后以 canvas 原子替换 loading；页面被逐出后恢复同高占位并提供 loading 标记，不留下无法辨认的裸空白。
- 小文档逐页读取页面尺寸；超过 24 页时仅测量首尾页，并按最大页高比例预置全部页面。单页尺寸读取失败时继续处理其他页面，渲染成功后仍以实际画布高度校正。
- 占位高度变化前记录当前顶部可见页及其页内偏移，布局更新后恢复该锚点。滚动事件只记录锚点，不主动回写 `scrollTop`；只有页面尺寸确实变化时才安排恢复，避免与用户拖动滚动条相互抢占。
- 普通滚动和局部页面完成渲染不得调用缩放居中恢复。只有用户主动改变缩放时才保存并恢复视口中心，防止未缩放状态下发生页面回跳。
- PDF 滚动容器、侧栏控件和树节点交互必须标记 `data-node-view-no-drag` 并停止对应的 mousedown 事件，避免 Tiptap 块拖动接管 PDF 内部交互。
- 点击 PDF 后，普通滚轮只滚动该 PDF 页面容器；点击块外清除激活状态。滚轮状态按块共享且响应式，并只通过一条 `passive: false` 监听路径处理，避免 NodeView 更新中断或同一次滚轮重复滚动。
- PDF 页面容器的垂直滚动条在激活前就常驻并稳定占位，点击块不能改变可用宽度，避免 PDF.js 因滚动条出现而重新缩放、闪烁一次。
- PDF.js 的 canvas 宿主由渲染管理器独占子节点；Vue 不得在宿主内同时渲染 loading 等可变子节点，避免占位更新与 `replaceChildren` 竞争导致组件更新异常。

## 阅读位置缓存

- 每个 `pdfExcerptBlock` 按稳定 `blockId` 独立保存最后阅读位置，同时记录 `fileId`、当前页、视口中心在页面内的相对偏移和 `updatedAt`。同一 PDF 文件在多个节点中引用时，各节点仍分别恢复自己的位置。
- 阅读位置写入 `localStorage` 的 `tu:pdf-reading-positions`。滚动时以约 250ms 合并写入，页码跳转和组件卸载时补写；首尾页使用精确边界，避免依赖可变的像素 `scrollTop`。
- 缓存有效期固定为 30 天，最多保留最近更新的 120 个 PDF 节点。加载时忽略过期、无效、`fileId` 不匹配或超出当前 PDF 页范围的记录，不覆盖第一页的有效初始阅读。
- 恢复必须在节点挂载且页面尺寸可测量之后执行。恢复失败时最多等待数个渲染帧后退回 PDF 起始页，并开启后续滚动写入；初始化过程不得把保存位置误写成第一页。

## 验证要求

- E2E 覆盖：当前页随滚动更新、输入页码/上一页/下一页跳转、摘页范围外与非法输入提示；在当前可视页添加得到「未命名书签」、右键重命名、右键删除、刷新恢复、同级拖动后刷新保持顺序、拖入另一书签后刷新保持父子层级；多页 PDF 滚至后段后等待懒渲染，连续帧的 `scrollTop` 不得持续向顶部回跳；快速跳至大文档后段时，当前可视页必须在限定时间内由 canvas 替代 loading，离屏页继续保留合法懒加载占位。
- 涉及通用树的改动至少运行 `npm run type-check`、相关 Vitest 与对应 Playwright 用例；右键菜单还需验证视口边缘钳位、点击外部及 Escape 关闭。

## 划选笔记的资源校验

- 「发布笔记」会先幂等创建 PDF 裁剪节选（`page + clip`），再将笔记挂到该节选上。
- PDF 裁剪节选校验资源条目绑定的站内文件，不依赖资源类型的 code；因此自定义类型的资源只要通过 `accessUrls` / `sourceUrl` 关联了 PDF 文件，也可以发布划选笔记。
- 普通资源节选接口仍只支持 `book`、`document`、`web-link`；PDF 专用接口不会放宽普通节选的策略。
